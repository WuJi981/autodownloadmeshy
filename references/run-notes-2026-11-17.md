# 实战记录：2026-11-17 首次全流程跑通

这次是 skill 写好后的第一次真实使用，目标是「给一张角色图 → 出带贴图的 .blend」。
全流程跑通了，但中间踩了 12 个坑，其中 3 个是会让整条链路静默失败或交付错东西的硬坑。
下面是按发生顺序的完整记录 + 结论，后续任何 AI 接手请先看这份。

## 坑 1：chrome-devtools MCP 连的不是同一个浏览器（硬坑）

**现象**：已经用 `--remote-debugging-port=9222` 起了 Chrome，但 MCP 的 `list_pages` 只返回
`1: about:blank`，对它 `evaluate_script` 得到 `hook:false, auto:false`，而 `/json/list` 里明明是
`https://meshy.cn/workspace`。

**原因**：MCP 没配 `--browserUrl` 时会自己拉起一个独立实例（独立 profile），跟 9222 那个毫无关系。

**结论**：**别用 MCP 托管页面**。直接用 CDP（`/json/list` → `webSocketDebuggerUrl`），
已封装成 `scripts/cdp_driver.mjs`。若一定要 MCP，必须让它连 `--browserUrl=http://127.0.0.1:9222`。

## 坑 2：后台任务结束会带走 Chrome（硬坑）

**现象**：`chrome_debug.ps1` 放在后台任务里跑，脚本打印 `CDP_READY` 后任务结束，
过一会儿所有 CDP 调用变成 `ECONNREFUSED 9222`。

**原因**：Chrome 是那个后台任务的子进程，任务结束、进程树被回收时一起被杀了。
（当时正好在生成完成、要抓 GLB 的节骨眼上，白等一轮。）

**结论**：用 WMI 创建进程，脱离任务树：

```powershell
$cmd = '"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="...\meshy-cdp-profile" --no-first-run "https://meshy.cn/workspace"'
([wmiclass]"Win32_Process").Create($cmd) | Out-Null
```

`cdp_driver.mjs start` 已这么做。好处：profile 复用、登录态不丢，即使当前会话结束浏览器还在。

## 坑 3：中文路径把上传搞死了（硬坑）

**现象**：`DOM.setFileInputFiles` 返回成功，但页面停在「点击/拖放/粘贴图像」，
再试一次变成「图片上传失败，请再试一次」。

**原因**：含中文的路径（如 `D:\图片\某图.png`）经 PowerShell/命令行传参时被按 GBK 转码，
真正传给浏览器的路径是乱码，文件读不到。`Get-ChildItem` 里文件名显示成乱码，就是这个信号。

**结论**：
- 非 ASCII 路径先复制成 ASCII 名再传（`cdp_driver.mjs upload` 自动做，落在
  `%TEMP%/automeshy-cdp/upload_xxxxxxxx.png`）；
- 别用 shell 传中文参数；要传就写进 UTF-8 的 `.mjs` 里由 node 读。

**附带发现**：口述的文件名可能和磁盘上的实际文件名不一致。
**给图片路径时以磁盘实际文件名为准，先列目录核对**，别直接信口述。

## 坑 4：`probe().hasImage` 假阳性（硬坑，已修）

**现象**：第一版上传失败后，`automeshy.probe().hasImage` 仍然返回 `true`，
差点带着空图去点生成。

**原因**：旧实现是 `!!document.querySelector('img[src^="blob:"],img[src*="cdn-images"]')`，
而右侧「我的生成」列表里每个任务缩略图都是 `.../cdn-images/<uid>/tasks/<taskId>/...`，
必然命中。

**修复**：只认上传槽位自己的证据：

```js
function imageSlotFilled() {
  // 1) file input 上还挂着没被读走的文件
  // 2) 槽位出现 blob:/data: 预览
  // 3) 出现 .../uploads/ 的 CDN 图（任务缩略图是 .../tasks/，不算）
}
```

并额外返回 `uploadSlotEmpty`（占位文案「点击/拖放/粘贴图像」是否还在）做交叉验证。
真实上传成功后站点给的是 `.../cdn-images/<uid>/uploads/<id>.png`，与 `tasks/` 不同路径段，可稳定区分。

## 坑 5：多视图是会员项，点了就弹订阅（配置已修）

**现象**：按旧配置 `multiView: true` 去点「多视图」，立刻弹出
「订阅以使用多视角 / 订阅以解锁此功能 … Starter ¥58.4/月」。

**原因**：旧配置默认值是从截图抄的，当时不知道它是付费功能。面板上它带皇冠图标（👑），
「拆分」「姿势」「私有」也带皇冠——**带皇冠的都不是免费项**。

**修复**：配置改为

```json
"multiView": { "enabled": false, "clickForbidden": true, "reason": "点它会弹「订阅以使用多视角」…" }
```

`applySettings()` 对多视图一律 `skipped`，绝不点击。要开多视图必须先开通会员，人工改配置。

**弹窗怎么关**：`Escape` 不管用；点遮罩空白处（`[class*=overlay]` 左上角 +5px）才关得掉。

## 坑 6：「贴图」默认是关的，不开只能拿白模

**现象**：面板初始状态 `贴图 aria-checked=false`，估算 `1 分钟 / 20 积分`。

**原因**：Meshy 默认不生成贴图。

**结论**：生成前必须打开贴图。开完才出现「模型（Meshy 7 / Meshy N1）」与
「贴图分辨率（2K / 4K / 8K）」子项，估算变成 `2 分钟 / 30 积分`——这也是积分闸门取 30 的依据。

## 坑 7：合成鼠标事件点不动 shadcn 开关

**现象**：`automeshy.clickEl()`（`dispatchEvent(new MouseEvent(...))`）点了「贴图」，
状态没变。

**原因**：这类 shadcn/Radix 开关只认真实指针序列，合成事件被忽略。

**结论**：关键开关用 CDP `Input.dispatchMouseEvent`（mouseMoved → mousePressed → mouseReleased），
坐标取自 `getBoundingClientRect()` 中心。`cdp_driver.mjs settings` 已实现，并在点完复核
`aria-checked`。

## 坑 8：裸 fetch 调 `/meshyd-api` 会 401

**现象**：自写的轮询脚本一直报 `TypeError: list.find is not a function`，
一查响应是 `{"code":"MissingToken","result":"Missing access token"}`。

**原因**：`/meshyd-api/*` 需要 cookie 里的 access_token 作为 `Authorization: Bearer`，
只带 `credentials:"include"` 不够。

**结论**：用 `automeshy` 内置的 `api()` 封装（已经处理 token 解码），
或 `automeshy.waitTask / findTexturedTask / taskDetail`，别自己写 fetch。

## 坑 9：一次生成产出两个任务，抓错就没贴图（硬坑）

**现象**：`waitTask()` 返回的 `taskId` 是 `<任务 ID A>`，但点击生成后立刻看到的第一个新任务
是 `<任务 ID B>`，两者三角面数一模一样（813,132），顶点数不同（442,977 vs 406,414）。

**原因**：Meshy 7 把「几何」和「贴图」拆成两个任务：

- `result.generate.modelUrl` → 白模
- `result.texture.modelUrl` + `result.texture.textureUrls[]`（colorMap / metallic / roughness / normal）→ 带贴图

**结论**：用任务详情判定，不能用面数/时间猜。
`automeshy.findTexturedTask(prevIds)` 会轮询并只认 `result.texture.*` 非空的那个。

## 坑 10：`saveGlb` 下载落到了不知道的地方

**原因**：`meshyfree.saveGlb()` 是页面里 `<a download>` 触发浏览器下载，
没设 `Browser.setDownloadBehavior` 就不知道落哪。

**结论**：抓取前先 `Browser.setDownloadBehavior({behavior:"allow", downloadPath})`，
然后轮询目录等 `.glb` 出现（`.crdownload` 消失）。`cdp_driver.mjs capture` 已内置，
并把路径写进 `%TEMP%/automeshy-cdp/state.json`。

## 坑 11：钩子要赶在模型加载前

**现象**（本次未发生，但差点）：Chrome 被杀后重启，页面状态全没，必须在 `openTask()` 之前
重新注入 hook。

**结论**：`Page.addScriptToEvaluateOnNewDocument` 注入（等价 initScript），再 `Page.navigate`。
只有这样才能包住启动时创建的解密 Worker；导航后再注入就漏。
`cdp_driver.mjs inject` 固定这个顺序。

## 坑 12：交付物核对不能只看脚本 println

**结论**：`finalize_download.py` 输出里必须逐行看到 `IMG: … packed=True`，
并且要**打开预览图肉眼确认贴图真的贴上去了**（本次预览可见黑发、肤色、裙装色差，
而不是灰模）。脚本说成功 ≠ 视觉上正确。

## 给下一次的最短路径

```bash
# 把 <你> 换成你的 Windows 用户名
S="C:\Users\<你>\.agents\skills\autodownloadmeshy\scripts"
node "$S\cdp_driver.mjs" start
node "$S\cdp_driver.mjs" inject
node "$S\cdp_driver.mjs" login --timeout=600     # 等用户手动登录
node "$S\cdp_driver.mjs" upload "<图片绝对路径>"
node "$S\cdp_driver.mjs" settings
node "$S\cdp_driver.mjs" generate --credits=30
node "$S\cdp_driver.mjs" wait --timeout=900
node "$S\cdp_driver.mjs" capture
node "$S\cdp_driver.mjs" blend "<GLB路径>" "<输出目录>" "<名称>"
```

仍要人做的一步：**登录**（账号密码/验证码只能用户自己输）；**积分不足时停下告知**。

## 仍然存在的边界

- 多视图、8K 贴图、私有许可证都要会员，一律不点，需要就提示用户先开通。
- 登录态存在 `%TEMP%\meshy-cdp-profile`，清临时目录就会掉登录。
- 生成结果是 gltfpack 压缩 + webp 贴图的 GLB，Blender 3.6+ 实测可正常导入并打包；
  更低版本未验证。
